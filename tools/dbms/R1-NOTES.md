## 2. `ResidBlkT` の反例（最小・8 列）

    M = (0,0,0)(1,1,1)(2,1,0)(1,1,0)(2,2,1)(3,1,0)(3,0,0)(2,0,0)

BMS 3 行 z<2 の**標準形**（`core.isstd` で確認）。末尾を
`(2,1,0)` / `(2,2,0)` / `(2,2,1)` に替えた 3 つも同じく反例。

### 何が起きているか（手で追える）

* 上の行列に対し `conv3` は `off = 1`（`p = (1,1,1)`, `p.1 = 1`）で
  `lad0` の枝に入り、`ps = (0,0)` なので `e = 1` のとき `qlab = (1,0)`。
* `units_split` は最初の柱 `(1,1,0)` がそのまま `qlab` なので **`U = []`**。
  `q = (1,1,0)`（深さ 1 = `p.1`、ラベル `(1,0)` = `qlab`）。
* `Aq = split0(q, r2) = [(2,2,1),(3,1,0),(3,0,0),(2,0,0)]`。
* `blk = [p] + A + U = [(1,1,1),(2,1,0)]`、
  `pre = contrPre(...) = [(2,2,1),(3,1,0)]`。`Aq[:2] == pre` で**一致する**。
* したがって

      rest2 = Aq[2:] = [(3,0,0), (2,0,0)]
                        ^^^^^^^ 深さ 3   ^^^^^^^ 深さ 2 < 3   ← **森**

* `conv_resid` は 2 周する。`rd = dmap_at(st, 3-1) = dmap[2] = 4`、
  2 周目は `rd = max(0, 4 - (3-2)) = 3`。
* 像は `(0,0,0)(1,0,0)(2,1,0)(3,2,1)(4,1,0)(4,0,0)(3,0,0)` で
  **DBMS 標準形**・`blockok 0` を満たす。行 0 の並びは `0 1 2 3 4 4 3`。
  **末尾の `4 3` が `convResid` の 2 本の木**である。

### `ImgBlockT3` 自体は森でも壊れない（測った）

森が 488 回発火する接頭辞族 15746 個と、`k+1 < |dmap|` が出る族 31605 個、
**合わせて 47351 個で `blockok 0` の破れ 0**。
⟹ **`conv3` は直さなくてよい。直すのは仮定の書き方だけ。**

### なぜ「`<=7` 列で 0」だったのか（構造の説明）

`split0` から**無条件に**言えるのは次の 1 本だけである。

> **補題 A** `Aq = (split0 q r2).1` かつ `q.1 = p.1` なので
> **`∀ c ∈ Aq, p.1 + 1 ≤ c.1`**。`rest2 = Aq.drop |pre|` は `Aq` の接尾辞
> なので同じ下界を持つ。

つまり `rest2.head.1 = p.1 + 1` のときは、それが `Aq` の**最小の深さ**なので
**単一の木は自動**である（`<=7` 列の 338 発火のうち **328** がこれ）。

問題は `rest2.head.1 > p.1 + 1` のとき、すなわち **`pre` が `Aq` の木の
途中で切れる**ときである。`pre` は `blk = [p]+A+U` の写し（深さ +1）で、
`blk` の最後の木は**もとの場所では完結している**（次の柱が `q`、深さ `p.1`）。
ところが**写しの側 `Aq` は `q` の引数ブロックの終わりまで続く**ので、
写しが尽きたあとに `q` の次の子（深さ `p.1+1`）が来てよい。そこが森になる。

`gen3 <=7` では「深い先頭」が **6 回**しか起きず、しかも 6 回とも
**そこで行列が終わっていた**（`rest2` の長さが 1）。1 列足すだけで森になる。
上の反例はまさに `<=7` の 6 例のうちの 1 つ

    (0,0,0)(1,1,1)(2,1,0)(1,1,0)(2,2,1)(3,1,0)(3,0,0)

に `(2,0,0)` を足したものである。

## 3. 直し方: `BlkOK rd` ではなく **`BlkOK d`**

`convResid` の結果について `BlkOK` の 8 節を、開始深さを
**`rd`** にした場合と**外側の `conv3` の `d`** にした場合の両方で数えた。

| 母集団 | `convResid` 発火 | `BlkOK rd` の破れ | 破れた節（内訳）| **`BlkOK d` の破れ** |
|---|---:|---:|---|---:|
| `gen3 <=7` | 338 | 0 | — | **0** |
| 展開閉包 46855 | 5236 | 0 | — | **0** |
| **`gen3 <=8` 全数** | 2414 | **32** | 節 6: 32 / 節 2: 16 | **0** |
| 反例 4 個 | 4 | **4** | 節 6: 4 | **0** |
| 接頭辞 `(2,1,0)(1,1,0)` <=9 列 | 1539 | **488** | 節 6: 488 / 節 2: 220 | **0** |
| 接頭辞 `(2,1,0)(1,1,0)` <=10 列 | 12872 | **5253** | 節 6: 5253 / 節 2: 2242 | **0** |
| 接頭辞 `(2,1,0)(3,1,0)` <=10 列 | 331 | **62** | 節 6: 62 / 節 2: 36 | **0** |

**破れるのは `BlkOK rd` の節 6 `∀ c ∈ res.1, rd ≤ c.1`（森の枝と 1 対 1）と、
その巻き添えの節 2 `rd ≤ |res.2.ST|` の 2 本だけ**である。
`rd` を外側の `d` に替えると **8 節すべてが全母集団で違反 0**。
破れ数は**森の枝の回数とちょうど一致する**（節 6 の列と `resid_FOREST` が同数）。`blk_step` が組み立てたいのは
`BlkOK d`（外側）なので、**`BlkOK d` を直接もらうのがいちばん素直**である。

### Lean に渡す形（命題 1 行）

    def ResidBlkT2 : Prop :=
      ∀ (rest : TrioSeq) (d rd : ℕ) (Lr : List Lent) (ps pw : ℕ × ℕ)
        (st : St) (nx : Option Col) (off : ℕ),
        rd ≤ st.ST.length → DmOK st →
        (∀ c ∈ rest, d + (rest.headD (0,0,0)).1 ≤ rd + c.1) →
        BlkOK d st (convResid rest rd Lr ps pw st nx off)

側条件 `∀ c ∈ rest, d + rest.head.1 ≤ rd + c.1` は
「木を 1 本降りるたびに開始深さが `m0 - tail.head.1` だけ下がるが、
それでも `d` を割らない」を書いたもので、**`convResid` の再帰でそのまま保たれる**
（`rd' = rd - (m0 - m1)`, `head' = m1` を入れると同じ式になる）。
実測: `rd` の `max(0, ...)` の**切り詰めは一度も起きない**（全母集団で 0 回）ので、
引き算は素直に伸びる。

### 呼び出し点で側条件が出ること

補題 A から `∀ c ∈ rest2, p.1 + 1 ≤ c.1` なので、側条件は

    d + rest2.head.1 ≤ rd + p.1 + 1

に落ちる。`rd` の 2 つの枝で:

* **`rd = d + 1 + e` の枝**（`rest2 = []` または `rest2.head.1 = p.1+1`）:
  `d + p.1 + 1 ≤ d + 1 + e + p.1 + 1` は自明。
* **`rd = dmapAt dmap k` の枝**（`k = rest2.head.1 - 1 ≥ p.1 + 1`）:
  `dmap[k] ≥ d + (k - p.1)` が要る。これが**節 10**（下）である。

## 4. `DmapInT`: 真。ただし「範囲内の中ほど」も起きる

### 4.1 `<=7` 列の 2 例（要求どおり全部書き出す）

どちらも `off = 1`, `p = (1,1,1)`, `e = 1`, `d = 1`, `k = 2`。

    M   = (0,0,0)(1,1,1)(2,1,0)(1,1,0)(2,2,1)(3,1,0)(3,0,0)
    M'  = (0,0,0)(1,1,1)(2,1,0)(1,1,0)(2,2,1)(3,1,0)(3,1,0)
    rest2 = ((3,0,0),) / ((3,1,0),)
    dmap  = [0, 3, 4]                       |dmap| = 3
    ST    = [(0,0),(0,0),(1,0),(2,1),(1,0)] |ST|   = 5
    dmap[k] = dmap[2] = 4
    d ≤ dmap[k] ≤ |ST|  ⟺  1 ≤ 4 ≤ 5       ✔

`k = 2 = |dmap| - 1` なので `DmOK`（`dmap.last + 1 = |ST|`）から
`dmap[k] = |ST| - 1` が出る。下界は `d + 2 ≤ |ST|`（`BlkOK_ST_ge`）から
`d ≤ |ST| - 2 < dmap[k]`。**この 2 例だけなら `dmapAt_bounds` で閉じる。**

### 4.2 ところが `k + 1 < |dmap|` は起きる（**課題 L13 の訂正**）

`Dbms3.lean` の `DmapInT` の docstring は「338 発火で一度も踏まれない」と
書いているが、**9 列で踏む**。接頭辞 `(0,0,0)(1,1,1)(2,1,0)(3,1,0)` の
全数展開 31605 個で **3 例**:

    M = (0,0,0)(1,1,1)(2,1,0)(3,1,0)(1,1,0)(2,2,1)(3,2,0)(4,1,0)(3,X,Y)
        X,Y ∈ {(0,0),(1,0),(2,0)}
    d = 1, k = 2, dmap = [0,3,4,5]  (|dmap| = 4), |ST| = 6, dmap[2] = 4
    k + 1 = 3 < 4 = |dmap|          ← DmapInT の第 2 項がここで効く
    d ≤ dmap[k] ≤ |ST|  ⟺  1 ≤ 4 ≤ 6   ✔

同じ接頭辞を **10 列**まで伸ばすと `k+1 < |dmap|` は **39 例**になる
（`dmapAt` の枝 141 回のうち、範囲内 67 のうち 39）。

⟹ **`dmapAt_bounds`（`k` が `|dmap|` か `|dmap|-1`）では閉じない。**
`d ≤ dmap[k]` と `dmap[k] ≤ |ST|` を**本当に**出す道具が要る。
なお 39 例すべてで `d ≤ dmap[k] ≤ |ST|` は成り立つ（違反 0）。

### 4.3 `k ≤ |dmap|`（`DmapInT` の第 1 項）は**証明できる**

`|dmap|` は「最後に処理したもとの柱の深さ + 1」である
（`st['dmap'] = st['dmap'][:c.1] + [dd]` なので、柱 `c` を処理した直後は
必ず `|dmap| = c.1 + 1`）。`cU` の直後にいるので、最後に処理した柱は
`blk[-1] = ([p]+A+U)[-1]` で、`|dmap| = blk[-1].1 + 1`。
一方 `pre[-1].1 = blk[-1].1 + 1 = |dmap|` で、`rest2.head` は
**行列の中で `pre[-1]` の直後の柱**である。BMS の標準形は
「隣の柱の行 0 は高々 +1」なので

    rest2.head.1 ≤ pre[-1].1 + 1 = |dmap| + 1
    ⟹ k = rest2.head.1 - 1 ≤ |dmap|                    ∎

実測（全母集団の `dmapAt` の枝 **9000 回超**）:

    k > |dmap|                                        **0 回**
    |dmap| = blk[-1].1 + 1（上の証明の要）  縮約の発火 全部で真
      gen3<=7  338/338 / 接頭辞族 <=9 列 1539/1539（不一致 **0**）
    rest2.head.1 ≤ pre[-1].1 + 1                      **0 違反**

⚠ Lean で厳密にやるときの注意: `|dmap| = blk[-1].1 + 1` は
「`cA` / `cU` が最後に処理したもとの柱が `blk[-1]` である」と同値だが、
`cA` の中で入れ子の縮約が起きると `q` と `pre` の列は**飛ばされる**ので、
「最後に処理した柱 = ブロックの最後の柱」は自明ではない。
実測は 100% だが、**帰納の 1 節として立てる**必要がある
（候補: `res.1 ≠ [] → res.2.dmap.length = (最後に処理した柱).1 + 1`、
すなわち `BlkOK` の節 5 `res.1.last.1 + 1 = |res.2.ST|` の `dmap` 版）。

帰納で保たれる理由（コードから）:

`cU` は深さ `d+1` で先頭 `p.1`、`cB` は深さ `d` で先頭 `p.1`、
`cR` は深さ `rd` で先頭 `rest2.head.1`。どれも
`d' + (j - m') ≥ d + (j - p.1)` を満たす向きに**ずれている**。

| 展開閉包 | 1181746 x2 | **0** | 1966 / 178 |
| 接頭辞族 <=10 列 | 2200967 x2 | **0** | 228 / 384 |

さらに的撃ちの追試: `gen3 <=7` で `dmap[k] = |ST|` **ちょうど**になる行列 42 個を
**+3 列まで全数展開**（6928 個）しても破れ 0。

**課題 L12 の訂正**: L12 の表は「`∀ k ∈ dmap, k < |ST|`」を測って
6/32 の違反を報告し、「`dmapAt` の範囲内を `|ST|` で抑える道具は無い」と

`DmOK`（`dmap.last + 1 = |ST|`）と合わせると 節 11 は

    ∀ k < |dmap|, dmap[k] ≤ dmap.last + 1

と同値で、「`dmap` は最後の項より 1 だけ深いところまでは出っ張ってよい」。
狭義単調は**偽**のままだが、`≤ |ST|` は**真**である。これが L12 で
「道具が無い」と判定された箇所の答えである。

## 6. まとめ: `ImgBlockT3` に残る仮定の新しい形

    ResidBlkT   ✘ 偽（8 列の反例）  →  ResidBlkT2（`BlkOK d` ＋ 側条件）
    DmapInT     ✔ 真（違反 0）      →  節 10 ＋ 節 11 から出る
                                       第 1 項 `k ≤ |dmap|` は §4.3 で証明ずみ

    足すべき BlkOK の節: 節 9（弱）/ **節 10**（強・これだけでよい）/ **節 11**

節 10 と 節 11 はどちらも**全 `conv3` 呼び出し**で違反 0（陽性対照つき）。
`conv3` 側は**直さない**（反例の像は全部 `blockok 0` で DBMS 標準形）。

## 6.5 Lean 側への推奨（課題 L14 として）

### (a) `ResidBlkT2` は**仮定にしなくてよい**（帰納の中で証明できる）

側条件 `H(rest, rd, d) := ∀ c ∈ rest, d + rest.head.1 ≤ rd + c.1` は
`convResid` の再帰でそのまま保たれる:

    次の木の開始深さ  rd' = rd - (m0 - m1)   （m1 = tail.head.1）
    H(tail, rd', d) ⟺ ∀ c ∈ tail, d + m1 ≤ rd - m0 + m1 + c.1
                    ⟺ ∀ c ∈ tail, d + m0 ≤ rd + c.1     ← H(rest, rd, d) そのもの

しかも `H` から `c := rest.head` を取ると `d ≤ rd` が出て、
`rd - (m0 - m1) ≥ d ≥ 0` なので **`max(0, ·)` の切り詰めは起きない**
（実測でも全母集団で切り詰め 0 回）。`convResid` は `conv3 head` を
`|head| ≤ |rest| < |M|` で呼ぶので、`blkInv_aux` の**強い帰納の中に入る**。
⟹ `ResidBlkT` は**仮定から消せる**。

### (b) 残る Lean の仕事は `BlkOK` に 2 節足して帰納で通すこと

    節 10  M ≠ [] → ∀ j ≥ M.headI.1, j < |res.2.dmap| →
             d + (j - M.headI.1) ≤ res.2.dmap[j]
    節 11  ∀ k < |st.dmap|, st.dmap[k] ≤ st.ST.length     （状態の不変量。DmOK の仲間）

節 10 は帰納で素直に通るはず（`cA` は `dd+1` / 先頭 `p.1+1`、`cU` は `d+1` /
先頭 `p.1`、`cB` は `d` / 先頭 `p.1`、`cR` は `rd` / 先頭 `rest2.head.1` で、
どれも `d' + (j - m') ≥ d + (j - p.1)` の向きにずれている）。
**節 11 の帰納は未検討**で、ここが唯一の残り。実測は違反 0 だが証明は別である。

### (c) `DmapInT` は消える

    第 1 項 `k ≤ |dmap|`      §4.3（`|dmap| = pre[-1].1` ＋ BMS の隣接 +1）
    下界 `d ≤ dmap[k]`        節 10（`k ≥ p.1+1` を入れる）
    上界 `dmap[k] ≤ |ST|`     節 11
