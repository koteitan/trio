## 2. `ResidBlkT` の反例（最小・8 列）

    M = (0,0,0)(1,1,1)(2,1,0)(1,1,0)(2,2,1)(3,1,0)(3,0,0)(2,0,0)

BMS 3 行 z<2 の**標準形**（`core.isstd` で確認）。末尾を
`(2,1,0)` / `(2,2,0)` / `(2,2,1)` に替えた 3 つも同じく反例。

### 何が起きているか（手で追える）

* 上の行列に対し `conv3` は `off = 1`（`p = (1,1,1)`, `p.1 = 1`）で
  `lad0` の枝に入り、`ps = (0,0)` なので `e = 1` のとき `qlab = (1,0)`。
* `units_split` は最初の柱 `(1,1,0)` がそのまま `qlab` なので **`U = []`**。
  `q = (1,1,0)`（深さ 1 = `p.1`、ラベル `(1,0)` = `qlab`）。
* `Aq = split0(q, r2) = [(2,2,1),(3,1,0),(3,0,0),(2,0,0)]`。
* `blk = [p] + A + U = [(1,1,1),(2,1,0)]`、
  `pre = contrPre(...) = [(2,2,1),(3,1,0)]`。`Aq[:2] == pre` で**一致する**。
* したがって

      rest2 = Aq[2:] = [(3,0,0), (2,0,0)]
                        ^^^^^^^ 深さ 3   ^^^^^^^ 深さ 2 < 3   ← **森**

* `conv_resid` は 2 周する。`rd = dmap_at(st, 3-1) = dmap[2] = 4`、
  2 周目は `rd = max(0, 4 - (3-2)) = 3`。
* 像は `(0,0,0)(1,0,0)(2,1,0)(3,2,1)(4,1,0)(4,0,0)(3,0,0)` で
  **DBMS 標準形**・`blockok 0` を満たす。行 0 の並びは `0 1 2 3 4 4 3`。
  **末尾の `4 3` が `convResid` の 2 本の木**である。

### `ImgBlockT3` 自体は森でも壊れない（測った）

森が 488 回発火する接頭辞族 15746 個と、`k+1 < |dmap|` が出る族 31605 個、
**合わせて 47351 個で `blockok 0` の破れ 0**。
⟹ **`conv3` は直さなくてよい。直すのは仮定の書き方だけ。**

### なぜ「`<=7` 列で 0」だったのか（構造の説明）

`split0` から**無条件に**言えるのは次の 1 本だけである。

> **補題 A** `Aq = (split0 q r2).1` かつ `q.1 = p.1` なので
> **`∀ c ∈ Aq, p.1 + 1 ≤ c.1`**。`rest2 = Aq.drop |pre|` は `Aq` の接尾辞
> なので同じ下界を持つ。

つまり `rest2.head.1 = p.1 + 1` のときは、それが `Aq` の**最小の深さ**なので
**単一の木は自動**である（`<=7` 列の 338 発火のうち **328** がこれ）。

問題は `rest2.head.1 > p.1 + 1` のとき、すなわち **`pre` が `Aq` の木の
途中で切れる**ときである。`pre` は `blk = [p]+A+U` の写し（深さ +1）で、
`blk` の最後の木は**もとの場所では完結している**（次の柱が `q`、深さ `p.1`）。
ところが**写しの側 `Aq` は `q` の引数ブロックの終わりまで続く**ので、
写しが尽きたあとに `q` の次の子（深さ `p.1+1`）が来てよい。そこが森になる。

`gen3 <=7` では「深い先頭」が **6 回**しか起きず、しかも 6 回とも
**そこで行列が終わっていた**（`rest2` の長さが 1）。1 列足すだけで森になる。
上の反例はまさに `<=7` の 6 例のうちの 1 つ

    (0,0,0)(1,1,1)(2,1,0)(1,1,0)(2,2,1)(3,1,0)(3,0,0)

に `(2,0,0)` を足したものである。

## 3. 直し方: `BlkOK rd` ではなく **`BlkOK d`**

`convResid` の結果について `BlkOK` の 8 節を、開始深さを
**`rd`** にした場合と**外側の `conv3` の `d`** にした場合の両方で数えた。

| 母集団 | `convResid` 発火 | `BlkOK rd` の破れ | 破れた節（内訳）| **`BlkOK d` の破れ** |
|---|---:|---:|---|---:|
| `gen3 <=7` | 338 | 0 | — | **0** |
| 展開閉包 46855 | 5236 | 0 | — | **0** |
| **`gen3 <=8` 全数** | 2414 | **32** | 節 6: 32 / 節 2: 16 | **0** |
| 反例 4 個 | 4 | **4** | 節 6: 4 | **0** |
| 接頭辞 `(2,1,0)(1,1,0)` <=9 列 | 1539 | **488** | 節 6: 488 / 節 2: 220 | **0** |
| 接頭辞 `(2,1,0)(1,1,0)` <=10 列 | 12872 | **5253** | 節 6: 5253 / 節 2: 2242 | **0** |
| 接頭辞 `(2,1,0)(3,1,0)` <=10 列 | 331 | **62** | 節 6: 62 / 節 2: 36 | **0** |

**破れるのは `BlkOK rd` の節 6 `∀ c ∈ res.1, rd ≤ c.1`（森の枝と 1 対 1）と、
その巻き添えの節 2 `rd ≤ |res.2.ST|` の 2 本だけ**である。
`rd` を外側の `d` に替えると **8 節すべてが全母集団で違反 0**。
破れ数は**森の枝の回数とちょうど一致する**（節 6 の列と `resid_FOREST` が同数）。

`blk_step` が組み立てたいのは `BlkOK d`（外側）なので、
**`BlkOK d` を直接もらうのがいちばん素直**である。

### Lean に渡す形（命題 1 行）

    def ResidBlkT2 : Prop :=
      ∀ (rest : TrioSeq) (d rd : ℕ) (Lr : List Lent) (ps pw : ℕ × ℕ)
        (st : St) (nx : Option Col) (off : ℕ),
        rd ≤ st.ST.length → DmOK st →
        (∀ c ∈ rest, d + (rest.headD (0,0,0)).1 ≤ rd + c.1) →
        BlkOK d st (convResid rest rd Lr ps pw st nx off)

側条件 `∀ c ∈ rest, d + rest.head.1 ≤ rd + c.1` は
「木を 1 本降りるたびに開始深さが `m0 - tail.head.1` だけ下がるが、
それでも `d` を割らない」を書いたもので、**`convResid` の再帰でそのまま保たれる**
（`rd' = rd - (m0 - m1)`, `head' = m1` を入れると同じ式になる）。
実測: `rd` の `max(0, ...)` の**切り詰めは一度も起きない**（全母集団で 0 回）ので、
引き算は素直に伸びる。

### 呼び出し点で側条件が出ること

補題 A から `∀ c ∈ rest2, p.1 + 1 ≤ c.1` なので、側条件は

    d + rest2.head.1 ≤ rd + p.1 + 1

に落ちる。`rd` の 2 つの枝で:

* **`rd = d + 1 + e` の枝**（`rest2 = []` または `rest2.head.1 = p.1+1`）:
  `d + p.1 + 1 ≤ d + 1 + e + p.1 + 1` は自明。
* **`rd = dmapAt dmap k` の枝**（`k = rest2.head.1 - 1 ≥ p.1 + 1`）:
  `dmap[k] ≥ d + (k - p.1)` が要る。これが**節 10**（下）である。

## 4. `DmapInT`: 真。ただし「範囲内の中ほど」も起きる

### 4.1 `<=7` 列の 2 例（要求どおり全部書き出す）

どちらも `off = 1`, `p = (1,1,1)`, `e = 1`, `d = 1`, `k = 2`。

    M   = (0,0,0)(1,1,1)(2,1,0)(1,1,0)(2,2,1)(3,1,0)(3,0,0)
    M'  = (0,0,0)(1,1,1)(2,1,0)(1,1,0)(2,2,1)(3,1,0)(3,1,0)
    rest2 = ((3,0,0),) / ((3,1,0),)
    dmap  = [0, 3, 4]                       |dmap| = 3
    ST    = [(0,0),(0,0),(1,0),(2,1),(1,0)] |ST|   = 5
    dmap[k] = dmap[2] = 4
    d ≤ dmap[k] ≤ |ST|  ⟺  1 ≤ 4 ≤ 5       ✔

`k = 2 = |dmap| - 1` なので `DmOK`（`dmap.last + 1 = |ST|`）から
`dmap[k] = |ST| - 1` が出る。下界は `d + 2 ≤ |ST|`（`BlkOK_ST_ge`）から
`d ≤ |ST| - 2 < dmap[k]`。**この 2 例だけなら `dmapAt_bounds` で閉じる。**

### 4.2 ところが `k + 1 < |dmap|` は起きる（**課題 L13 の訂正**）

`Dbms3.lean` の `DmapInT` の docstring は「338 発火で一度も踏まれない」と
書いているが、**9 列で踏む**。接頭辞 `(0,0,0)(1,1,1)(2,1,0)(3,1,0)` の
全数展開 31605 個で **3 例**:

    M = (0,0,0)(1,1,1)(2,1,0)(3,1,0)(1,1,0)(2,2,1)(3,2,0)(4,1,0)(3,X,Y)
        X,Y ∈ {(0,0),(1,0),(2,0)}
    d = 1, k = 2, dmap = [0,3,4,5]  (|dmap| = 4), |ST| = 6, dmap[2] = 4
    k + 1 = 3 < 4 = |dmap|          ← DmapInT の第 2 項がここで効く
    d ≤ dmap[k] ≤ |ST|  ⟺  1 ≤ 4 ≤ 6   ✔

同じ接頭辞を **10 列**まで伸ばすと `k+1 < |dmap|` は **39 例**になる
（`dmapAt` の枝 141 回のうち、範囲内 67 のうち 39）。

⟹ **`dmapAt_bounds`（`k` が `|dmap|` か `|dmap|-1`）では閉じない。**
`d ≤ dmap[k]` と `dmap[k] ≤ |ST|` を**本当に**出す道具が要る。
なお 39 例すべてで `d ≤ dmap[k] ≤ |ST|` は成り立つ（違反 0）。

### 4.3 `k ≤ |dmap|`（`DmapInT` の第 1 項）は**証明できる**

`|dmap|` は「最後に処理したもとの柱の深さ + 1」である
（`st['dmap'] = st['dmap'][:c.1] + [dd]` なので、柱 `c` を処理した直後は
必ず `|dmap| = c.1 + 1`）。`cU` の直後にいるので、最後に処理した柱は
`blk[-1] = ([p]+A+U)[-1]` で、`|dmap| = blk[-1].1 + 1`。
一方 `pre[-1].1 = blk[-1].1 + 1 = |dmap|` で、`rest2.head` は
**行列の中で `pre[-1]` の直後の柱**である。BMS の標準形は
「隣の柱の行 0 は高々 +1」なので

    rest2.head.1 ≤ pre[-1].1 + 1 = |dmap| + 1
    ⟹ k = rest2.head.1 - 1 ≤ |dmap|                    ∎

実測（全母集団の `dmapAt` の枝 **9000 回超**）:

    k > |dmap|                                        **0 回**
    |dmap| = blk[-1].1 + 1（上の証明の要）  縮約の発火 全部で真
      gen3<=7  338/338 / 接頭辞族 <=9 列 1539/1539（不一致 **0**）
    rest2.head.1 ≤ pre[-1].1 + 1                      **0 違反**

⚠ Lean で厳密にやるときの注意: `|dmap| = blk[-1].1 + 1` は
「`cA` / `cU` が最後に処理したもとの柱が `blk[-1]` である」と同値だが、
`cA` の中で入れ子の縮約が起きると `q` と `pre` の列は**飛ばされる**ので、
「最後に処理した柱 = ブロックの最後の柱」は自明ではない。
実測は 100% だが、**帰納の 1 節として立てる**必要がある
（候補: `res.1 ≠ [] → res.2.dmap.length = (最後に処理した柱).1 + 1`、
すなわち `BlkOK` の節 5 `res.1.last.1 + 1 = |res.2.ST|` の `dmap` 版）。

さらに的撃ちの追試: `gen3 <=7` で `dmap[k] = |ST|` **ちょうど**になる行列 42 個を
**+3 列まで全数展開**（6928 個）しても破れ 0。

**課題 L12 の訂正**: L12 の表は「`∀ k ∈ dmap, k < |ST|`」を測って

と同値で、「`dmap` は最後の項より 1 だけ深いところまでは出っ張ってよい」。
狭義単調は**偽**のままだが、`≤ |ST|` は**真**である。これが L12 で
「道具が無い」と判定された箇所の答えである。

## 6. まとめ: `ImgBlockT3` に残る仮定の新しい形

    ResidBlkT   ✘ 偽（8 列の反例）  →  ResidBlkT2（`BlkOK d` ＋ 側条件）
    DmapInT     ✔ 真（違反 0）      →  節 10 ＋ 節 11 から出る
                                       第 1 項 `k ≤ |dmap|` は §4.3 で証明ずみ

    足すべき BlkOK の節: 節 9（弱）/ **節 10**（強・これだけでよい）/ **節 11**

節 10 と 節 11 はどちらも**全 `conv3` 呼び出し**で違反 0（陽性対照つき）。
`conv3` 側は**直さない**（反例の像は全部 `blockok 0` で DBMS 標準形）。

## 6.5 Lean 側への推奨（課題 L14 として）

### (a) `ResidBlkT2` は**仮定にしなくてよい**（帰納の中で証明できる）

側条件 `H(rest, rd, d) := ∀ c ∈ rest, d + rest.head.1 ≤ rd + c.1` は
`convResid` の再帰でそのまま保たれる:

    次の木の開始深さ  rd' = rd - (m0 - m1)   （m1 = tail.head.1）
    H(tail, rd', d) ⟺ ∀ c ∈ tail, d + m1 ≤ rd - m0 + m1 + c.1
                    ⟺ ∀ c ∈ tail, d + m0 ≤ rd + c.1     ← H(rest, rd, d) そのもの

しかも `H` から `c := rest.head` を取ると `d ≤ rd` が出て、
`rd - (m0 - m1) ≥ d ≥ 0` なので **`max(0, ·)` の切り詰めは起きない**
（実測でも全母集団で切り詰め 0 回）。`convResid` は `conv3 head` を
`|head| ≤ |rest| < |M|` で呼ぶので、`blkInv_aux` の**強い帰納の中に入る**。
⟹ `ResidBlkT` は**仮定から消せる**。

### (b) 残る Lean の仕事は `BlkOK` に 2 節足して帰納で通すこと

    節 10  M ≠ [] → ∀ j ≥ M.headI.1, j < |res.2.dmap| →
             d + (j - M.headI.1) ≤ res.2.dmap[j]

# 課題 R2: 森の枝で成り立つ**弱い形**（証明つき）

## R2-0. 結論

    (T1) 木ごとに「出した柱の深さ >= その木の開始深さ `rd_k`」   … 実測 違反 0
    (T2) 開始深さは**真に下がる**  `rd_{k+1} = rd_k - (m0_k - m0_{k+1})`, 差 >= 1
    (T3) どの木の `rd_k` も**外側の `d` 以上**                     … 実測 違反 0
    ⟹ `max(0, ·)` の切り詰めは**死んでいる**（証明できる。下）

`BlkOK_app'`（開始深さが下がってもよい連結、L13 で証明ずみ）を (T1)(T2)(T3) で
鎖状につなぐと、`convResid` 全体が **`BlkOK d`**（`rd` ではなく外側の `d`）を
満たす。これが求める弱い形である。

## R2-1. `rd` は真に下がる（証明）

`conv_resid` の切り方から

    i = 「`rest[i].1 < m0` になる最初の添字」（無ければ `len(rest)`）
    head = rest[:i],  tail = rest[i:]

なので **`tail ≠ [] → tail[0].1 < m0`**。したがって

    δ_k := m0_k - m0_{k+1} ≥ 1
    rd_{k+1} = max(0, rd_k - δ_k)

* もとの深さ `m0_k` は**真に下がる**（狭義単調減少）。
* 補題 A から `m0_k ≥ p.1 + 1` なので、
  **木の本数は高々 `rest[0].1 - p.1` 本**（ループは必ず止まる。実測の最大は 2 本）。
* 切り詰めが無ければ**望遠鏡的に** `rd_k = rd_1 - (m0_1 - m0_k)`。

## R2-2. `rd = 0` の穴は**塞がる**（証明）

切り詰めが起きると `rd_{k+1} = 0` になり、深さ 0 の柱が出て `BlkOK d`（`d ≥ 1`）が
壊れる。**しかし起きない。** 側条件

    (H)  ∀ c ∈ rest,  d + rest[0].1 ≤ rd + c.1

を仮定すると、`c := rest[0]` から `d ≤ rd`。さらに `c := 最後の木の頭` から

    rd_k = rd_1 - (m0_1 - m0_k) ≥ d ≥ 0

なので**引き算は負にならない**＝ `max(0, ·)` は恒等写像。しかも (H) は
再帰でそのまま保たれる:

    H(tail, rd - δ, d)
      ⟺ ∀ c ∈ tail, d + m0_{k+1} ≤ rd - m0_k + m0_{k+1} + c.1
      ⟺ ∀ c ∈ tail, d + m0_k ≤ rd + c.1        ← H(rest, rd, d) の tail への制限

**⟹ (H) 1 本で (T2)(T3) と「切り詰めなし」が全部出る。**

### 呼び出し点で (H) が出ること

補題 A（`∀ c ∈ rest2, p.1 + 1 ≤ c.1`）から (H) は

    d + rest2.head.1 ≤ rd + p.1 + 1

に落ちる。`rd` の 2 つの枝で:

* **`rd = d+1+e` の枝**: この枝の条件は `rest2 = []` または
  `rest2.head.1 = p.1+1`。後者なら `rest2.head` が `Aq` の**最小の深さ**なので
  **そもそも単一の木**（ループは 1 周で終わる）。式も
  `d + p.1+1 ≤ d+1+e + p.1+1` で自明。
* **`rd = dmapAt dmap k` の枝**（`k = rest2.head.1 - 1 ≥ p.1+1`）:
  `dmap[k] ≥ d + (k - p.1)` が要る。これが**節 10**である（§5, 実測 違反 0）。

**⟹ 森は `dmapAt` の枝でしか起きない。** 実測でも一致する
（`gen3 <=8`: 森 32 ⊂ 深い先頭 83、`rest2.head.1 = p.1+1` の 2303 件では森 0）。

## R2-3. Lean に渡す 1 行の命題

# 課題 R7: **`SeqEmbT3` は偽**（＝ `OrderT3` も偽）。反例は 8 列 + 9 列（2026-08-29）

## R7-0. 測り方（母数の 2 乗は要らない）

`seqlex` は **Python のタプルの自然順序とまったく同じ**:

    seqlex [] N          = (N ≠ [])                    ⟺ () < N
    seqlex (p::M) []     = False                       ⟺ ¬((p,…) < ())
    seqlex (p::M) (q::N) = collt p q ∨ (p=q ∧ seqlex M N) ⟺ タプルの辞書式

しかも `seqlex` は**狭義全順序**（三分律）なので

## R29 — `ImgCofinalT3` を 1 回で決着させる（2026-08-29）

### 結論（1 行）

> **`ImgCofinalT3` は 決着せず。理由は計算量ではなく方法の限界:
> 逆像 `B` の長さに上界が無いので、`gen3` の像の表では「逆像なし」を

### 何を測ったか（`tools/dbms/r47.py`）

§R28 で `gen3('BMS', L, zcap=1) = ST_TS ∩ {len <= L}` が確定したので、
`stts` の枝刈りも `preimage_try` の発見性も要らず、**像の表**で決められる**はず**だった。

    表   gen3(BMS,<=8,zcap=1) = 781605 個（= ST_TS ∩ {len<=8}）  485s
         像の集合 781605 件、**像の最大の長さ 16**              31s
    A    gen3(BMS,<=7,zcap=1) の |A|>1 77281 個から**無作為に** 3000 個

結果:

    **逆像あり**            8866
    逆像なし                6818
    測れない（|T| > 16）    32316   <- 全体の 67%

### なぜ決着しないか（これが本題）

`conv3` は**長さを縮める**。`gen3(BMS,<=7,zcap=1)` 全数で測った:

    |B| ->  min |conv3 B| .. max
      1  ->   1 ..  1        5  ->   4 ..  9
      2  ->   2 ..  4        6  ->   5 .. 12
      3  ->   3 ..  5        7  ->   5 .. 13
      4  ->   4 ..  8

`min |conv3 B|` は |B| におよそ半分の速さでしか伸びない（|B|=7 で 5）。
したがって **|T| = 16 の T の逆像 B は |B| = 30 くらいでもありうる**。
`|B| <= 8` の表で「入らない」と出ても、それは `ImgCofinalT` の反例ではなく
**表が浅いだけ**。表を 9 列に伸ばしても上限が 16 -> 18 になるだけで、
必要な 30 列には（7.7M -> 天文学的なので）絶対に届かない。

⟹ **像の表による全数判定は `ImgCofinalT` に原理的に使えない。**
R25 の「候補 1 件が像に入らない」も同じ理由で**反例ではない**（撤回）。
`preimage_try`（発見的）で見つからないことと合わせても、非像の証明にはならない。

決着させるには **`conv3` の逆向きの構文的な補題**（`T` の形から `|B|` の上界を出す）が
要る。数値実験ではもう進まない。

## R29-5 — `WSnoc` の**両側とも健全な**反証器（`tools/dbms/r49.py`）

`probe_snoc.minstage` は `W` の代役でしかない（上の R29-4）。ここでは Lean の `W`
そのものを、**下界（True が健全）** と **上界（False が健全）** で挟んだ。
節 3 が実装できることが分かったのが鍵。

### 節 3 が計算できる理由（2 つの観察）

1. **`domT M m` の m は一意。** `domT M m := lev M (|M|-1) = m+1 /\ 親が無い`。
   `lev M (|M|-1)` が m を決めるので、`exists m < u` は **1 通り**しか調べなくてよい。
2. **`[] in W m`（節 1: `|[]| = 0 <= 1`, `lev [] 0 = 0`）かつ `based []`**、
   そして `graft M [] = M.dropLast`（Lean の `graft_nil`）。
   ⟹ **節 3 ならば `M.dropLast in X`**。これが節 3 の**必要条件**。

### 下界 `Wlo`（True が健全 —— 任意の u で `M in W u`）

`oper M n` は「最後の列が零」または「親が無い」とき `Pred M` を返す。これは
**n に依らない**ので、節 2 の `forall n >= 1` が**有限で確かめきれる**。

    Wlo(M) := (|M| <= 1 /\ lev M 0 = 0)
           \/ (|M| >= 2 /\ (最後の列が零 \/ 親が無い) /\ Wlo(Pred M))

＝「**孤児の塔**」。切り詰めが一切入らないので **True は本物**。

### 上界 `Wup`（False が健全 —— `Wup = False` なら本当に `M not in W u`）

節 2 を `n in 1..N` に切り（通りやすくなる = 上界、`False` は有限の証人つきで健全）、
節 3 を上の必要条件に緩める（同じく上界）。

### 反証の形

    Wlo(C) = True（C in W u が**確定**）
    かつ hasParent(C ++ [p], srow, |C|)
    かつ Wup(C ++ [p], u) = False（**not in W u が確定**）
    ⟹ **`WSnoc` の本物の反例**

両側とも健全なので、出れば反例。`probe_snoc` の `minstage` にはこの性質が無い。

    u = 0,1,2: 結果が完全に同じ ⟹ この母集団では節 3 が一度も効かない

⟹ `WSnoc` を u >= 1 で本当に試すなら **u >= 4** で測る必要がある。

### この計測から出た **Lean 側の補題**（既存かどうかを確認済み）

反証器を書くために必要だった観察。**(W2)(W4) は既に Lean にある**
（`Wset.lean` の `hgr [] (W_nil m) based_nil` が 6 箇所、
`Wtower2.lean` の `oper_eq_graft_nil_of_domT` + `graft_nil` が 8 箇所）。
**新しいのは (W1) と (W3) の 2 本**（`grep` では見つからなかった）。

**(W1) `domT` の m は一意 —— 節 3 の存在量化は消せる** —— **見当たらない**

    domT M m  :=  lev M (|M|-1) = m + 1  /\  ¬ hasParent M (srow M (|M|-1)) (|M|-1)

第 1 連言が m を決めるので

    (∃ m < u, domT M m /\ P m)
      ↔  (0 < lev M (|M|-1)  /\  ¬ hasParent M (srow M (|M|-1)) (|M|-1)
           /\  lev M (|M|-1) - 1 < u  /\  P (lev M (|M|-1) - 1))

**(W2) 節 3 ならば `M.dropLast ∈ X`** —— **Lean に既にある**

`|[]| = 0 ≤ 1` かつ `lev [] 0 = 0` なので **`[] ∈ W m`（節 1）**、`based []`（`based_nil`）、
`graft M [] = M.dropLast`（`graft_nil`）。z := [] を代入するだけ。

    (∃ m < u, domT M m /\ ∀ z ∈ W m, based z → graft M z ∈ X)  →  M.dropLast ∈ X

**(W3) (W2) から出る `W` の除去則** —— **見当たらない。これが本命**

    M ∈ W u → 2 ≤ |M| → (∀ n ≥ 1, M⟦n⟧ ∈ W u) ∨ M.dropLast ∈ W u

`W u` の展開（節 1 は `|M| ≥ 2` で潰れる）に (W2) を当てるだけ。
**節 3 の `∀ z ∈ W m` という無限量化を `dropLast` 1 本に落とせる**ので、
`WSnoc` の帰納で使える形になっているはず。

**(W4) 孤児の塔（`Wlo` の中身）** —— **Lean に既にある**
（`oper_eq_graft_nil_of_domT`）。ここでは計算模型の下界として使った。

最後の列が零列または親を持たないとき `M⟦n⟧ = Pred M`（n に依らない）なので

    (最後の列が零 ∨ ¬hasParent) → Pred M ∈ W u → M ∈ W u

これを繰り返すと、`lev = 0` の 1 列から孤児を積んだものは**すべて** `W u`（任意の u）。

### `Wlo` は弱い。そして**固定段数では閉じない**（`r50.py` / `r51.py`）

「孤児の塔に親付きの列を足して展開すると、また孤児の塔になるか」を測った
（母数: 孤児の塔 C 200 個 × 親が付く p 全部 = 5567 事例、n = 1..8）:

    n=1..8 すべて孤児の塔      3226  (58%)
    **n=2 で孤児の塔でない**   2341  (42%)

最小の反例が `Wlo` の弱さそのものを示している:

    C = (0,0,0),  p = (1,1,0)  ->  (C ++ [p])[2] = (0,0,0)(1,0,0)

`(0,0,0)(1,0,0)` は `W 0` の元（展開すると `(0,0,0)^n` で全部孤児の塔）だが、
最後の列 `(1,0,0)` は**行 0 に親を持つ**ので `Wlo` は落とす。
⟹ **`Wlo` は `W` の下界としては粗い。**

そこで「何段降りれば孤児の塔になるか」を測った（`r51.py`）:

    cert(M,0) := Wlo(M),   cert(M,d) := Wlo(M) or (forall n in 1..N, cert(M[n], d-1))

    段数 1        3226
    段数 6 以内に決まらず  2341     <- 段数 2..6 は **1 件も無い**

理由が分かった。上の例で `(C++[p])[n]` は

    n=1 -> (0,0,0)                        段数 0
    n=2 -> (0,0,0)(1,0,0)                 段数 1
    n=3 -> (0,0,0)(1,0,0)(2,0,0)          段数 2
    ...

と **n とともに必要な段数が伸びる**。`forall n >= 1` を取るので上限が無い。

⟹ **`WSnoc` は固定段数の展開では閉じない。**本物の（超限）帰納が要る。
数値実験でここを埋めることはできない。`Wup`/`Wlo` で挟んで反例が無いことを
確かめる、という今の使い方が数値でできる限界。

### 実行の勘どころ（次の人へ）

`Wup` の費用は **C が短いほど高い**。短い C に親付きの p を足すと展開が伸びて
`maxlen` に当たるまで `N^depth` を舐めるため。実測:

    N=4, depth=10, |C| <= 3   ->  500 秒で C を **11 個**しか処理できない
    N=3, depth= 8, |C| <= 3   ->  8 秒で C 300 個（4490 事例）
    N=3, depth=12, |C| 4..12  ->  397 秒で C 1200 個（35646 事例）

⟹ **N=3、depth 8..12 で回すこと。** N=4 は割に合わない。
`memo` は放っておくと 5GB まで育つので上限を切る（`R49BUDGET` 環境変数で
打ち切り時間も指定できる）。ログを 2 つのプロセスで同じファイルに書かないこと
（実際にやって結果を 2 回失った）。

### `refute.py` に照らして自分の `Wup` の穴を 1 つ直した
