# BMS -> DBMS 変換の調査メモ

対象: BM4-Analysis-2021.4.27.xlsx シート `To psi(I)` の A 列(BMS) / E 列(DBMS)、1638 行。

## 0. DBMS とは（yaBMS c/bms.c の実装から）

**展開規則は BM4 と完全に同一。違うのは標準形判定の「対角」だけ。**

| | 対角 diag[x][y] |
|---|---|
| BMS (BM4) | `x` |
| DBMS | `max(x-y, 0)` |

つまり DBMS の対角は `(0)(1)(2,1)(3,2,1)(4,3,2)(5,4,3)...`（末尾 0 は省略記法）で、
行 y は列 y からしか立ち上がれない。3 行版 (DTSS) の対角は
`(0,0,0)(1,0,0)(2,1,0)(3,2,1)(4,3,2)(5,4,3)...(k,k-1,k-2)`。

出典は Ecl1psed 氏の Discord 発言 (2019) のみ。一次資料はローカルに無い（trio-agent 調べ）。

## 1. 実測でわかったこと

### (a) 行数は保存される
シートの 1638 対で、BMS が n 行なら DBMS も n 行（n=1:28, 2:236, 3:1373）。
つまり **TSS (3 行 BM4) ⇔ DTSS (3 行 DBMS)** で閉じている。

### (a2) 順序検算: シートは順序同型として完璧（`order_check.py`）
f が順序同型なら任意の 2 行で `sign(cmp(bms_i,bms_j)) == sign(cmp(dbms_i,dbms_j))`。
cmpmat は同一システム内の標準形どうしなら健全なので、A 列どうし・E 列どうしで比較できる。

| | ペア数 | 違反 |
|---|---|---|
| Y=2 | 27,730 | **0** |
| Y=3 | 920,046 | 2（下記の誤記 2 件に由来） |

Y=3 の 2 件は行 1287/1288 と 1432/1433 で、**BMS 列が隣接行とまったく同じ**（列の写し落とし）:
```
1287 psi(W_(w3)*2) bms (0)(1,1,1)(2,1)(3,2,1)(4,2)(5,3,1)(5,3,1)(5,3,1)
1288 psi(W_(w3)*3) bms (0)(1,1,1)(2,1)(3,2,1)(4,2)(5,3,1)(5,3,1)(5,3,1)   ← (5,3,1) が 1 個足りない
```
つまり **DBMS 列は全域で正しい**。この検算はシートに無い入力（自分の出力）にも掛けられるので、
規則の当てずっぽうを潰すのに一番効く。

### (b) シートの検算
自作エンジン (`core.py`) で全 1638 対を標準形判定すると、
BMS 側 15 行 / DBMS 側 4 行が非標準形。うち数件は明らかな誤記
（`(3,20)`, `(3,32,1)`）。行 1098-1100 は両側とも非標準で、シート側の誤りらしい。
残り 1622 対を「使える対」として採点に用いる。

### (c) ord は展開規則だけで決まる（システム非依存）
行列 M の表す順序数は
```
ord(空) = 0
ord(M)  = ord(M-末尾列) + 1        (末尾列が全零)
ord(M)  = sup_n ord(M[n])          (それ以外)
```
で決まり、この定義に「BMS か DBMS か」は一切現れない。展開規則が共通だからである。
系として:

* **変換 f は「同じ順序数を表す DBMS 標準形を返す」写像**（＝標準形集合の順序同型）。
* **M が既に DBMS 標準形なら f(M) = M**（恒等）。
  実測: シートで DBMS 標準形でもある BMS 行列は 29 個（＝1 行行列）で、
  そのすべてで A 列 = E 列 ✅。

### (d) f は「行 0 の根」での分解について加法的
行 0 の値が 0 の列で区切ったブロック（＝順序数の和の項）ごとに変換して連結してよい。
```
f((0,0)(1,1)(0,0)) = f((0,0)(1,1)) ++ f((0,0)) = (0)(1)(2,1) ++ (0)
```
1622 対すべてでこの分解と矛盾しない。

### (e) 列数は保存されない（基本列がずれる）
```
BMS  (0,0)(1,1)(1,0)(2,1)(2,0)   = e0^w   (5 列)
DBMS (0)(1)(2,1)(2)              = e0^w   (4 列)
```
基本列は BMS 側が `e0^2, e0^3, ...`、DBMS 側が `e0, e0^2, ...` で **添字が 1 ずれる**。
DBMS の e0 = `(0)(1)(2,1)` が既に「コピー単位 (1,0)(2,1) を 1 個含む」形だから。
このため「展開アドレス（対角からのブラケット列）をそのまま再生する」方式は失敗する。

長さの差 len(DBMS)-len(BMS) の分布（1622 対）:
`-6:1, -5:11, -4:25, -3:82, -2:113, -1:99, 0:49, +1:216, +2:992, +3:27, +4:6, +6:1`

## 2. 素朴な構文規則 R1 / R2（`rule.py`）

**R1**: 先頭に DBMS 対角の長さ Y-1 の接頭辞を付け、各列を
`(a_0,...,a_{Y-1}) -> (a_0+(Y-1), a_1+(Y-2), ..., a_{Y-1}+0)` にずらす。
（BMS の `(0^Y)(1^Y)` が DBMS の `(0)(1)(2,1)...` に対応することから。）

**R2**: R1 をブロック（(d) の和の項）ごとに適用。

| 規則 | 正解数 / 1622 |
|---|---|
| R1 | 827 (51%) — Y=2 で 187/236 (79%)、Y=3 で 611/1357 (45%) |
| R2 | 835 (51%) |

**どちらも規則としては不正解**。長さが保存されないケース ((e)) を原理的に扱えない。

## 3. 正しい変換器 `convert.py`（原理は正しいが計算量が爆発する）

(c) から
```
f(0) = 空,  f(a+1) = f(a) ++ 全零列,  f(lim a) = sup_n f(a[n])
```
sup は「すべての f(a[n]) より大きい最小の DBMS 標準形」で、DBMS 対角から展開で降りて求める。
高速化: (c) の恒等ショートカット、(d) の加法性、基本列の接頭辞単調性を使った比較の早期確定。

小さい例（e0, e0*w, e0^2, z0, psi(W_2), psi(W_w) など）は正しく求まるが、
再帰が f(a[n]) を複数個要求するため深さについて指数的で、e0^w 以上で予算切れになる。

## 4. 本命の構文規則 R7 / R8（`rule.py`）

**BMS の 1 列が DBMS では「階段」になる**のが本質:
```
(1,1)   -> (1,0)(2,1)
(1,1,1) -> (1,0,0)(2,1,0)(3,2,1)
(2,1,1) -> (2,1,0)(3,2,1)     ← 階段の根 (1,0,0) が直前の列の像と共有されるので短い
(2,1)   -> (2,1)              ← 同上（直前が (1,0)）
```

### R7「影つき階段」
DBMS では、行 y (y>=1) の親になる列は「行 y-1 で 1 段深い**影**」でなければならない。
足りなければ影の列を挿入する（親ごとに 1 回だけ。以後は使い回す ＝ 階段の共有）。

```
shadow(p, 0) = img[p]
shadow(p, y) = shadow(p, y-1)                              … 行 y-1 の値が 1 以上なら
             = 新列 shadow(p,y-1) の行 0..y-1 に +1 を挿入   … さもなくば
T[y] = out[shadow(P_y(x), y)][y] + 1        (1 <= y <= t)
T[0] = max(out[img[P_0(x)]][0], out[shadow(P_t(x), t)][0]) + 1
```
（t = 列 x の最上位の非零行、P_y は BM4 の行 y の親。）

### R8 = R7 + コピー縮約
R7 の出力は順序数は合っているが**コピーが 1 個多い非標準形**になることがある
（§1(e) の添字ずれ）。そこで「良い部分の末尾がバッド部のコピー 1 個ぶんなら落とす」
縮約を、接頭辞ごとに標準形になるまで繰り返す。健全性の判定は
`expand(Z_red, n+1) == expand(Z, n)`（両者の sup が一致 ＝ 順序数不変）。

```
BMS  (0,0)(1,1)(1,0)(2,1)(2,0)
 R7  (0)(1)(2,1)(1)(2,1)(2)      ← 順序数は e0^w だが DBMS 非標準形
 R8  (0)(1)(2,1)(2)              ← 正解
```

### 採点（シートの使える 1622 対）

| 規則 | 合計 | Y=1 (28) | Y=2 (236) | Y=3 (1357) |
|---|---|---|---|---|
| R1（素朴なずらし） | 827 | 28 | 187 | 611 |
| R2（R1 をブロックごと） | 835 | 28 | ? | ? |
| R7（影つき階段のみ） | 330 | 28 | 215 | 86 |
| **R8（R7 + コピー縮約）** | 352 | 28 | **236/236**（シート誤り 2 件を補正後） | 89 (6.6%) |

**2 行（ペア数列）は R8 でほぼ解けた（234/236）。3 行はまだ。**

残る Y=2 の 2 件（行 128 phi(3,z0) / 行 129 phi(3,phi(3,0))）は**シート E 列の誤りで、R8 が正しい**。
→ **R8 は Y=2 で 236/236。**

根拠 3 つ:

1. **綴り方の一貫性**。psi(W^k * α) の引数部は
   「α の DBMS の綴りから (0)(1) を落として row0 に +2」で書かれている。
   行 113/117/121/127 はこれに従うが、128/129 だけ従わない。
```
113 psi(W^2*e0)  base (0)(1)(2,1)(3,1)(3)      + (4,1)          ← e0=(0)(1)(2,1)
117 psi(W^2*z0)  base 同上                     + (4,1)(5,1)     ← z0=(0)(1)(2,1)(3,1)
121 psi(W^2*zz0) base 同上                     + (4,1)(5,1)(5)(6,1)(7,1)
127 psi(W^3*e0)  base (0)(1)(2,1)(3,1)(3,1)(3) + (4,1)
128 psi(W^3*z0)  base 同上                     + (4,1)(4,1)     ← ✗ (4,1)(5,1) のはず
129 psi(W^3*phi(3,0))                          + (4,1)(4,1)(4,1)← ✗ (4,1)(5,1)(5,1)
```
2. **BMS 列は正しい**。行 117 と 128 の BMS の末尾はどちらも (3,1)(4,1)（構造も同一）で、
   OCF ラベル phi(3,z0) とも合う。誤っているのは E 列だけ。
   シート値の引数部 (4,1)(4,1) を -2 して (0)(1) を戻すと (0)(1)(2,1)(2,1) = e1 なので、
   E 列が指しているのは psi(W^3 * e1)。行 129 は同様に psi(W^3 * e2)。
3. **順序検算は判別できない**（両方とも DBMS 標準形で、順序も矛盾しない）。
   ただし R8 を Y=2 の全 236 行に使うと **違反 0・全部標準形・重複なし**で、
   順序埋め込みとして健全。

順序検算の使い方の注意: **1 行だけ差し替えて検算しても意味がない**。
128 だけ R8 に差し替えると 129 と衝突するが、128 と 129 を両方差し替えると違反 0 になる。
系統的にずれている誤りは、族ごと差し替えて初めて見える。

R1 の合計が大きいのは Y=3 で「たまたま当たる」形が多いだけで、規則としては R8 が正しい方向。

### 3 行で落ちる理由（診断）
縮約 `reduce_once` は「行列全体のバッドルートの直前」しか見ていないので、
入れ子になったコピーを落とせない。例:
```
BMS  (0,0,0)(1,1,1)(1,1,0)(2,2,1)(2,1,0)          5 列
true (0)(1)(2,1)(3,2,1)(3,1)                      5 列   ← (1,1,0)(2,2,1) が丸ごと吸収される
R8   (0)(1)(2,1)(3,2,1)(2,1)(3,2,1)(3,1)          7 列
```
trio-agent の測定（`~/proofs/trio/tmp/probe_bms2dbms_prefix.py`）とも整合:

* f は後続列について厳密（17/17 で `f(M)[:-1] == f(M[:-1])`）
* 列接頭辞 8940 組のうち **93.9% は「像の最後の 1 列を除いて接頭辞」**
  ＝ f は先読み 1 列の左→右トランスデューサでほぼ書ける
* 食い違う最後の 1 列はほぼ**持ち上げ**（差分 (0,1,0) が 2001 件 ＝ 行 1 が +1）
  「そこで行列が終わるなら低く、後ろに何か続くなら 1 段上げる」
* 残り 6.1% (548 組) が上の**吸収**。A_pre がコピー標識の途中で終わるときだけ起きる

### R9 / R10（事後縮約の拡張）— 失敗、原因も判明
逐語重複 `Z[i-L:i] == Z[i:i+L]` を 1 個落とす一般の縮約を、
共終性 `{Z[n]}` と `{Z_red[m]}` の相互共終で健全性判定するようにしてみた（`normalize2/3`）。

**うまくいかない。理由: cmpmat は非標準形に対して信用できない。**
```
Z  = (0)(1)(2,1)(1)(2,1)(2)(3,1)   ← R7 の出力（非標準形）
c  = (0)(1)(2,1)(2)(3,1)           ← 正解
expand(Z,1) = (0)(1)(2,1)(1)(2,1)(2)   … 順序数は e0^w だが非標準形
expand(c,1) = (0)(1)(2,1)(2)           … 同じ e0^w の標準形
cmpmat では前者 < 後者 と出る（先頭 7 番目が 1 vs 2）ので共終性判定が落ちる
```
つまり**書いてから消す方式は原理的に苦しい**。trio-agent の言う通り、
「そもそも書かない（被覆）」側で直すのが正しい。

## 5. 3 行への挑戦（このセッションの結論: 未完）

### (a) 写像はトランスデューサではない — 「正規形の再計算」である
R7 の最初の食い違いを 1357 行で調べると、**1180 件が同一の 1 か所**だった:
```
BMS (0,0,0)(1,1,1)(2,1,0)... に対し R7 は 5 列目に (4,1,0) を書くが、正解は (4,2,0)
```
この (4,1,0) / (4,2,0) の分かれ目をデータで確かめると:

| BMS の 4 列目以降 | 5 列目 | 件数 |
|---|---|---|
| 無し / (1,1)/(1,1)(2,2,1)(3,1)... | (4,1,0) | 47 |
| (1,1)(2,2,1)**(3,2)**... 以降 | (4,2,0) | 915 |

しきい値は「ord(M) がその段を超えるか」に見える。
`(0)(1)(2,1)(3,2,1)(4,1)` = psi(W_w*W)、`(4,2)` はその次の段。

⚠️ **ここで一度「規則では原理的に書けない」と結論したが、それは誤り**（trio-agent が反証）。
有限の先読みで決まる。`lookahead.py` で測った結果（シート Y=3 の 1357 行）:
```
先読み 0 列: キー 2618, 曖昧 1247
先読み 1 列: キー 3732, 曖昧  988
先読み 2 列: キー 4887, 曖昧  586
先読み 3 列: キー 6124, 曖昧  226
先読み 4 列: キー 7429, 曖昧   55
先読み 5 列: キー 8732, 曖昧   21
先読み 6 列: キー 9955, 曖昧    0   ← 窓 6 列で矛盾ゼロ
```
（a[:k+L] -> e[k] という素朴な添字合わせの代理指標。窓の存在証明ではないが、
「原理的に不可」の反証にはなる。シートの深さが有限なので窓が伸びる可能性は残る。）

さらに、あの 1180 件の分岐点は局所的な特徴でほぼ決まる。col2=(2,1,0) の像の行 1 値 v は:

| 特徴 | 曖昧な行 |
|---|---|
| col2 の行 0 子孫の行 1 最大 | 283 / 962 （0 のときだけ曖昧。1 以上なら必ず v=2） |
| 全体の行 1 最大 | 871 |
| 直後の列の行 1 | 412 |

残る 283 行も、6 列目 `(3,1,0)` なら v=1 / `(3,2,0)` なら v=2 で完全に分かれる。
つまり **v は「後で名指されるレベル（番地）」**。trio-agent の言う
「列が名指すレベルは行 1 の数値ではなく祖先鎖の深さ」と同じ現象で、
正しい設計は窓を広げることではなく**レベルを状態として持ち回ること**。

（trio-agent の実測でも、列接頭辞 8940 組の 93.9% は「像の最後の 1 列を除いて接頭辞」だが、
残りが本質的で、その 1 列は「後ろに何か続くと 1 段上がる」持ち上げだった。同じ現象。）

### (b) 正しい定式化: 貪欲な正規形構成（`greedy.py`）
正規形どうしは cmpmat（辞書式）順なので
```
f(M) = 「ord <= ord(M) をみたす DBMS 標準形」のうち辞書式最大
```
であり、列を左から 1 本ずつ「ord(M) を超えない範囲で辞書式最大」に選べば組める。
終了判定に等号は要らない（どの列を足しても超える ⇒ 終わり）。

### (c) 必要な部品: システムをまたぐ順序数比較（`ocmp.py`）
ord は展開規則だけで決まるので、BMS 標準形と DBMS 標準形の ord を直接比べられる。
後続/極限の場合分けによる相互再帰で実装した:

| 場合 | 規則 |
|---|---|
| 行列として同一 | 0 |
| 同じシステムの標準形どうし | cmpmat |
| 加法分解できる | 項別に比較（項は非増加） |
| succ vs succ | 前者どうし |
| succ vs lim | ord(A-1) < ord(B) なら -1、さもなくば +1 |
| lim vs lim | ∃m A<=B[m] なら -1 / ∃n A[n]>=B なら +1 / どちらも無ければ 0 |

**未完の原因は「両方とも極限」の等号判定**。証人が無いことを無限に確かめる必要がある。
最終的に次の形に落ち着いた（`_eq_lim`）:

1. **添字ごと一致**（十分条件）: `A[i] == B[i]` が i=1,2 で成り立てば等しい。
   実測でこの形が Y=2 の 95%、Y=3 の 68%。
2. **相互共終**: 基本列は増加列なので `∃m<=K: A[n] <= B[m]` は `A[n] <= B[K]` と同値。
   よって添字ずらし D を試すだけでよい（K^2 通り見る必要は無い）。
   `A[2] <= B[2+D]` かつ `B[2] <= A[2+D]` を D=1 で確かめる。

この形にしてから**誤答は 0 になった**（シート Y=2 先頭 80 行で 誤り 0）。
残るのは**速度だけ**:

| | 結果 |
|---|---|
| シート Y=2 先頭 80 行、1 行 3 秒 | 等号正解 16 / 誤り **0** / タイムアウト 64 |

正解する 16 行は e0 〜 e0^e0 の範囲。z0 = psi(W^2) 以上でタイムアウトする。
`ocmp(z0_dbms, z0_bms)` は 20 秒で 100 万回の再帰呼び出しに達して終わらない。
等号の証明が「A[2] と B[2] の等号」を要求し、それが 1 段ずつ上の順序数の等号に
なるので、鎖が長い場合に爆発する。

効いた高速化:
* `core.fsindex` の二分探索に `n <= len(b)+4` の上限（無いと巨大行列を作って死ぬ）
* `ocmp` に加法分解（`e0*2` どうしが一瞬で終わる）
* `core.flat` / `ocmp.blocks` のメモ化
* **学習した f のマップ** (`ocmp.fmap`): 等号を証明したら `fmap[B_bms] = A_dbms` を記録し、
  以後 `ocmp(X_dbms, B_bms)` は `cmpmat(X, fmap[B])` で済ませる（同一システムなので健全）。
  ヒット率は高い（100 万回中 37 万回）が、それでも z0 は落ちなかった。

### (d) 捨てた方針とその理由
* **展開アドレスの再生**: 基本列が一致しないので原理的に不可（§1(e)）。
* **sup 再帰 `f(lim)=sup f(a[n])`**（`convert.py`）: 原理は正しいが、
  f(M[n]) が M より長い行列を要求するので再帰が膨らむ。
  シートの Y=2 全 236 行に対し **22 正解 / 17 誤 / 197 タイムアウト**（840 秒）。実用にならない。
* **事後縮約**（R9/R10）: cmpmat が非標準形に対して信用できないので健全性判定ができない（§4）。

## 6. R23: 2 行と 3 行を同じ規則で（現時点の最良）

trio-agent の指摘（レベルを状態として持ち回る）に従って作り直したら大きく伸びた。

### 設計
1. **階段（影の列）**: 行 y (y>=1) の親になる列は DBMS では「行 y-1 で 1 段深い影」で
   なければならない。足りなければ影を挿入する（親ごとに 1 回、以後は使い回す）。
2. **深さ（レベル）**: 影を何段まで使うかは列ごとに変わる。実測すると
   **分岐するのは (a,1,0) 型の列だけ**で、他は常に t 段（浅い方）。
   (a,1,0) (a>=2) の深さは「次の 1 列」＋「そのブロックのレベル状態」で決まる:
   ```
   深さ 0（浅い）: 次が無い（末尾）
                 または 次がアンカー（next[0]==next[1] かつ next!=(1,1,1)）で、
                        かつ lm - pm <= 1
   深さ 1（深い）: それ以外
     pm = 同じ行 0 ブロックで x より前に現れる行 1 の最大値
     lm = 同じ行 0 ブロックで x より後に現れる行 1 の最大値
   ```
   `lm - pm <= 1` が「レベルの状態」。**まだ 2 段以上深いレベルが名指されていない
   あいだは浅いまま**、という意味で、trio-agent の言う「番地」に相当する。
3. **縮約**: BMS は「コピー 1 個 + 印」で書くところを DBMS は「印」だけで書くので
   出力に逐語重複が出る（§1(e) の添字ずれ）。標準形になるまで重複区間を 1 つずつ落とす。

### 総当たりでも作れない 66 行
```
BMS  (0,0,0)(1,1,1)(2,1,0)(1,1,0)(2,2,1)(3,2,0)
true (0)(1)(2,1)(3,2,1)(4,2)
```

BMS の 4 列 `(2,1,0)(1,1,0)(2,2,1)(3,2,0)` が DBMS の 1 列 `(4,2,0)` に潰れる。
