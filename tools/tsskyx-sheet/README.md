# Tsskyx's BMS Analysis との照合

Tsskyx 氏の私物シート `Tsskyx's BMS Analysis`（`../papers/tsskyx-bms-analysis.xlsx`）
を読んで、本プロジェクトの `tools/build_omega_alpha.py` と
`ebp2bms/{sheet,algorithm}/{1,2}` に突き合わせるツール。

**シート本体も抽出結果もリポジトリに入れないこと**（非公開資料）。
`extract.py` の出力先は既定で `tmp/`（`.gitignore` 済み）。

    python3 tools/tsskyx-sheet/extract.py          # 可読テキストに展開
    python3 tools/tsskyx-sheet/check.py            # 照合（正誤表を当てた状態）
    python3 tools/tsskyx-sheet/check.py --raw      # 正誤表なしの素の状態

## シートの読み方

1 シートが 4 つの列帯（Buchholz / Bashicu / Idealized / Rachel の各ヒドラ）に
分かれ、縦にブロックが並ぶ。帯の順番と幅はリビジョンで変わるので、
1 行目のヘッダから読む（シートごとに違うこともある）。1 ブロック = 1 順序数で、小さい順。
ブロックの中身は「ヒドラの絵」＋（あれば）「行列の行」。

- 絵のセル 1 つがノード 1 つ。帯の中での列番号が数列中の位置、
  根の行からの高さが行 0 の森での深さ（= 行列の `x`）、
  セルの値がそのノードのラベル（= その列が表す psi の添字）。
- 行列の行は列を桁文字列で書いたもの。末尾の 0 は省く（`221` = (2,2,1)、
  `1` = (1,0,0)）。

Bashicu 帯のラベルは `ebp2bms/algorithm/2` の読みそのもので、
**z=0 なら y、z=1 なら w**。Idealized 帯は別系なのでこの規則は当てはまらない。

## 照合結果（2026-08-23 版の xlsx）

373 ブロック・321 行列を対象。

- A 列の読み: 321/321 一致。`(x,y,0) = Omega_y`, `(x,y,1) = Omega_w` という
  algorithm/2 の読みが、Tsskyx 氏が独立に描いたラベルと全部一致する。
- B 順序と正規形: 違反 0。
- C psi_0(Omega_alpha) 行（行列同士）: 9/9 一致。
- D psi_0(Omega_alpha) 行（絵同士、行列を書いていないブロックも拾う）: 17/17 一致。
  alpha = 2, 3, w, w+1, w+2, w*2, w*2+1, w*3, w^2, w^2+1, w^2+2, w^2+w,
  w^2+w*2, w^2*2。
- E `ebp2bms/sheet/{1,2}` の表: 96/96 行が builder と一致。

## Idealized 帯の未解決（前リビジョンから変化なし）

Idealized 帯はラベル規則が別系（`(2,2,1)` が `w^2` など）でまだ特定できていない
ので、ラベルの照合はしていない。系に依らない検査（絵のノード数と行列の列数、
高さと x、順序）だけかけたところ 106 行列中 2 件ひっかかった。**要確認**。

- `Up to 0w^w` [14] 行 82: 絵は 11 ノードだが行列は AA82..AJ82 の 10 列。
  x=5 の列（AK82）が抜けている。並びからすると `551`。
- 同 [15] 行 88 が [14] 行 82 を超えない。AK82 を足しても解消しない。
  [14] の AH82 と [15] の AH88 が両方 `220` だが、絵のラベルは `w` と `w+1` で
  違うので、どちらかも直る必要がありそう。

Rachel 帯（20 行列）は問題なし。
