# G7: C2 の値と枠の一致

起動: `bash tmp/codex/run_seedfo_C2_matches_20261104.sh`。
Claude氏が起動する。nice15、親1本とworker3本。Leanの変更なし。

入力はG6の各チェックポイント。正常評価できた2665ソースのn=2/3を
それぞれ調べる。G6の評価不能1ソースもupstream.UNRESOLVEDで残す。

出力: `tmp/codex/seedfo_C2_matches_20261104/`。
各入力区画と同名のJSONに全行列、n、増える子、値の変化、全一致先を保存。
集計はsummary.json。ログは同名の.log。再実行で未完の区画から再開。

## 記録

1. CL_N(r)のうちprefixよりoが増える子を直接検出する。
   各子の新o、新vについて、M・prefix・Nの全列のo/vとの一致を列挙。
   Nの一致先には写し元と0始まりのブロック番号を付ける。
   rより前の列はcopy_number=null。写し元はgexpの位置の対応であり、
   行の値が文字通り等しいとは主張しない。
2. rの各途中状態と完全に等しい、Nの全ての枠を列挙。
   一致先の列、前の子の列番号の並び、次の子、残りの子、写し元を保存。
   本物の枠（次の数える子が存在する）だけを一致先とし、
   全子を入れ終えたoの状態を枠として数えない。
   r自身の同じ枠との自明な一致も保存するが、集計では
   他の列との一致を別欄にする。rの別の写し、kの写しも別集計。
3. prefixの旧oとNの新oを丸ごと保存し、psiの添字・引数・尾を比較。
   vも同様に比較。添字だけ/引数だけが変わる場合を区別。
   和の共通先頭と変わる残りを保存する。
   old + suffix = new を満たす最短の末尾も探すが、
   これは加法の等式の証人であり、一般に一意でない順序数の引き算ではない。

## 事前確認

16列例・n=2/3とbash構文の確認はexit0。
列9の新oはNの列1のoと一致し、添字だけが変わる。
列12の新oはNの列15（r=8のcopy_number=1）のoと一致。
列12では添字だけの変化ではない。
rの空の前状態には他列の枠の一致先があるが、
2つ目の前状態には他列の枠との完全一致がない。
この小例の結果を全件の結果とは扱わない。
